# Web 出面: 画面の表示要素の洗い出し (2026-09-06)

ブランチ `claude/web-page-high-quality-bfa367` の `web/src/pages/**` と部品を機械的に舐めて
「各画面に何が出ているか」を一覧にしたもの。何を出すかは Rust の DTO が決め、Astro は置くだけ
(`docs/ARCHITECTURE-web.md` INV-1)。DTO の列名は `web/src/lib/schema/*.ts`。

## 0. 全ページ共通の枠

| 場所 | 要素 |
|---|---|
| ヘッダ (`SiteHeader`) | サイト名 / 主要ナビ (ライブ・楽曲・アイドル・ユニット・会場・ブランド + お題・コールガイドは集計があるときだけ、`SiteMeta.primaryNav`) / 検索ボタン。現在地はパンくずに入口が居るかで決まる |
| パンくず (`Breadcrumbs`) | `SeoBlock.breadcrumbs` (ホーム → 入口 → 現在) |
| 詳細ページの脇 (`DetailLayout` → `OpenInApp`) | 「アプリ『アイドルライブDB』」の説明文 (`AppOpen.note`)、deeplink があるページ (ライブ・公演・お題) は「アプリで開く」、無ければ App Store |
| フッタ (`SiteFooter`) | データ基準日 (JST) / データの一覧 (主要ナビと同じ) / ABOUT (検索・このサイトについて) / APP (GitHub・App Store・Play Store・X・プライバシー・サポート・利用規約) / 非公式の断り書き (`footerNotes`) / JASRAC 許諾表示 |
| テーマ | `<body data-theme="idol:…|brand:…|neutral">` に Rust 生成の `themes.css` が 14 トークンを当てる。**ライト / ダークは `prefers-color-scheme` 追従のみ。手動トグルは意図して作っていない** (`BaseLayout.astro` 冒頭のコメント、`tokens.css` の `color-scheme: light dark` + `@media (prefers-color-scheme: dark)`、`theme.rs` も同じ media でダーク値を出す) |
| 検索 (`SearchBox`) | トップ・404・`/search/` に置く。`/search/` だけ wasm の island (曲・アイドル・ライブ・会場)。無効時は主要ナビの一覧へ誘導 |

## 1. トップ `/`

| 塊 | 要素 |
|---|---|
| ヒーロー | サイト名 (h1) / タグライン / 検索ボックス / 件数の帯 `StatStrip` (ライブ・公演・楽曲・アイドル・ユニット・会場、押すと一覧) |
| 今後のライブ | 先頭 1 件は `FeatureEvent` (日付バッジ・終了日・ブランド印・種別札・名前・会場・公演数)、残りは `EventRow`。空なら「今後の開催予定はまだ登録されていません」 |
| 最近の公演 | `ShowRow` (日付バッジ・ライブ名 + 公演名・曲数) 8 件 + 「開催済みのライブへ」 |
| ブランドから探す | `EntryCard` (記号・名前・紹介文 `previewDisplay`) |
| アプリで、もっと | 説明文 / App Store で見る / GitHub でデータに協力する |

## 2. ライブ

### 一覧 `/events/` `/events/upcoming/` `/events/past/` `/events/past/<年>/` `/events/brand/<brand>/`

| 要素 | 内容 |
|---|---|
| 切替 | 今後 / 開催済み (`scopeLinks`)、ブランドの札 (`brandLinks`)、年の札 (`yearLinks`) |
| 本体 | 年ごとの節 (`YearGroupSection`) に `EventRow` = 日付バッジ (年は節見出しにあるので落とす)・ライブ名・ブランド印・種別札 (フェス / リリイベ等の例外だけ) |
| 入口 (`/events/`) だけ | 今後の全部 + 開催済みの最新の年 (`recentPast`) + 「開催済みをすべて見る」(`next`)。各年ページは 1 つ前の年へ送る |

### 詳細 `/events/<id>/`

| 塊 | 要素 |
|---|---|
| ヒーロー | ブランド印 (押せる) / 種別 (`kindLabel`) / 「開催予定」札 / 名前 / 読み / 期間 (`dateDisplay`) / 合同ブランドの札 / 会場の札 (都市つき) / 件数の帯 |
| 公演 | `ShowRow` (日付バッジ・公演名・曲数)。空は EmptyState |
| 出演者 | 公演ごとに `Performer` (名前 + 主演 / ゲストの札) |
| 映像・音源 | 種別札・発売日・題名 (URL があれば押せる) |
| チケット | ラベル付き行 (`ticketRows`: 申込締切・抽選発表 等) + 「公式情報」リンク |

### 公演 `/shows/<id>/`

| 塊 | 要素 |
|---|---|
| ヒーロー | ブランド印 / 「開催予定」札 / 見出し = ライブ名 (押すとライブへ) + 公演の札 (`DAY2` 等) / 大きい日付バッジ / `Facts` (会場・ホール・開演 等、何を出すかは Rust) / 同じライブの公演の切替 (4 つまでは segmented、多ければ前後ページャ) / 件数の帯 |
| セットリスト | 区切り (`SetlistSection.label`: アンコール等) ごとに `SetlistRow` = 通し番号・ジャケ・曲名・注記 (`notes`)・ユニット表記の札・カバー札・編成の札 (`lineup.label`)・初披露の札・歌唱者 (`Performer`: アイドル名 / CV 名) と全員曲の畳み (`Fold`)・不参加の名前 (`lineup.missing`) |
| 歌唱者の表示 | `PerformerNamePref` の select (アイドル名 / CV 名 / アイドル名 + CV 名 / 公演に合わせる)。**キャラライブが実データ 0 件なので「公演に合わせる」は CV 名固定** |
| 出演者 | `RefList` |
| このライブの公演 | 兄弟公演 (ヒーローの切替と同じ材料) |

## 3. 楽曲

### 一覧 `/songs/` `/songs/brand/<brand>/` `/songs/all/`

| 要素 | 内容 |
|---|---|
| 切替 | ブランドの札 / よみの目次 (`KanaIndex`) / 絞り込みバー (`ListFilterBar`: 語で絞る・作家名・並べ替えの札 (よみ / 披露回数 / リリース) と向き・クリア。wasm が `queryBase` を土台に動く) |
| 行 (`SongRow`) | ジャケ / 曲名 + 種別の札 / ユニット・歌唱アイドル / 作曲・収録 (62rem 以上) / 初出日 (30rem 以下は落とす) / 披露回数 |
| 末尾 | 「派生曲・ライブ限定曲を含む全件」(`/songs/all/`、`noindex`。行は ref だけ) / 「タグから探す」(`/tags/`、タグの付いた曲があるときだけ) |

### 詳細 `/songs/<id>/`

| 塊 | 要素 |
|---|---|
| ヒーロー | ジャケ (Apple Music) / 種別 (`songTypeLabel`) / 曲名 / 読み / 歌唱アイドル (原唱者、多ければ `Fold`) / ブランド札 / ユニット札 (無ければ `unitLabel`) / Apple Music ボタン / 派生曲なら親への一文 / 件数の帯 (披露回数・歌唱アイドル数) |
| 歌詞とコールガイド | 許諾の断り書き → 「歌詞とコールガイドを読む」→ Worker から 1 曲だけ取得。行ごとに手拍子記号列・アンカー語の色敷き・語の真下 (追っかけは後ろ) のコール。凡例は使っている記号・強調だけ |
| 基本情報 | `factRows` (リリース・収録・シリーズ・再生時間・JASRAC 作品コード。値の無い行は出さない) |
| クレジット | 作詞 / 作曲 / 編曲 (`credits`) |
| ほかに歌ったアイドル | `otherArtists` (カバー等) |
| 派生曲 / 関連する曲 | `variants` / `related` (`RefList`) |
| 披露履歴 | `DatedRow` (日付バッジ・ライブ名・公演・N 曲目・「初披露」等の `ordinalLabel`) |
| よく歌うアイドル / よく一緒に披露される曲 | `RankingRow` (回数付き) |
| みんなの記録 | タグの札 (押すとタグの曲一覧) / お気に入り数 / ペンライトの色セットの数 (「N 通り」) |

### タグ `/tags/` `/tags/<tagId>/`

| 要素 | 内容 |
|---|---|
| `/tags/` | 曲の多い順に、色付きの札・説明・「公式」札・曲数 (`DatedRow`) |
| `/tags/<id>/` | 札 + 説明 + 並びの断り → `RankingRow` (順位・ジャケ・曲名・副題・付けた人数) → 「タグ」一覧へ戻る |

## 9. 出せるのに出していないもの (DTO にあって、どの部品も参照していない列)

`web/src/lib/schema` の列を `web/src` 全体で機械照合した結果。

| 列 | いまの扱い | 判断の候補 |
|---|---|---|
| `SongPage.durationDisplay` / `seriesDisplay` | 未表示 | `factRows` の「再生時間」「シリーズ」と重複 (同じ値を 2 経路で配っている)。DTO から落としてよい |
| `LyricsBlock.licenseNumber` | 未表示 | `licenseNote` の文に番号が入っているので重複。落としてよい |
| `IdolListPage.birthMonth` | 未表示 | 見出しが `title` に入っているので不要 |
| `UnitPage.isPermanent` | 未表示 | `kindLabel` で表しているので不要 |
| `VenuePage.aliasesDisplay` | 未表示 | `factRows` の「別名」と重複 |

## 10. アプリにあって Web に無いもの

アプリの画面 (`ImasLiveDB/Views/`): About / Calendar / CallGuideDashboard / Community / Events / Filtered /
Games / Idols / IntroDon / MyPage / Polls / Produce / Search / Settings / Share / Songs / Stats / Tags /
Timeline / Units。

| アプリの要素 | Web | 備考 |
|---|---|---|
| 参加記録・お気に入り・メモ・マイタグ・投票・コール編集・タグ付け | 無し (意図) | ログインが要る。出面は読むだけで、導線は「アプリで開く」 |
| アイドル画像ギャラリー | 無し (意図) | 版権物を載せない |
| カレンダー (月表示の予定) | 無し | 公開情報なので出せる候補。`/events/upcoming/` が年グループで代替 |
| 統計 (Stats) | 無し | 公開集計なら候補 (披露回数ランキング等はブランド・曲ページに一部) |
| タイムライン | 無し | 公開の年表なら候補 |
| クイズ (Games / IntroDon)・プロデュース | 無し (意図) | アプリ専用 |
| ペンライトの色そのもの | セット数 (「N 通り」) だけ | 色セットの鍵と票数 (`PenlightSetDto`) は来ているが、色にも票数にも展開していない |
| タグが似ているアイドル / ユニット | 無し | アプリの詳細にある。集計を焼き込めば出せる |
| 公演の「披露ユニット ・ 全 N/M 名」「全員集合！」 | 無し | ライブ詳細の出演情報。`EventCast` は主演 / ゲストまで |

## 11. まだ確かめていないこと

  `prefers-color-scheme: light` で全ページを一度見る必要がある。
