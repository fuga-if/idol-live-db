# `imas-mcp` の使い方 — 何が引けるか / どう組み合わせるか

> 設計と「なぜそうなっているか」は [`ARCHITECTURE-mcp.md`](ARCHITECTURE-mcp.md)。
> こちらは**使う側**の手引き。ここに書いた手順は実際に通したものだけを載せる。

## 1. できることの地図 (25 ツール)

| 用 | ツール | 何が返るか |
|---|---|---|
| **入口** | `resolve` | 人の言葉 → id。**get_* を呼ぶ前に必ずここを通る** |
| | `search` | 曲/人/ライブ横断。どの種別に何件あるかを一度に |
| | `vocabulary` | ブランド・種別の取りうる値・各表の件数・収録期間。取りうる値が分からないとき |
| **1 件の全体像** | `get_idol` | プロフィール(属性・誕生日・趣味・特技)・持ち歌・出演 |
| | `get_song` | 作家・CD・名義・原唱者・披露履歴 |
| | `get_event` / `get_show` | 公演一覧 / セットリスト全文 (曲順・歌唱者・出演者) |
| **並べる** | `list_idols` | 誕生月・星座・出身地・属性・CV・ユニットで |
| | `list_songs` | ブランド・種別・原唱者・CD シリーズ・時期で |
| | `list_events` | ブランド・年・会場・種別・今後/過去で |
| | `list_shows` | **公演単位**。出演者数・主演・セトリ有無で絞れる |
| **人と曲** | `idol_songs` | 原唱 / ソロ / ユニット名義 / 披露を分けて返す |
| | `song_performances` | その曲の披露履歴 (日付・公演・そのときの歌唱者・通算何回目) |
| | `songs_for_cast` | **顔ぶれで歌える曲**。`max_missing` で「あと 1 人いれば」も |
| **セトリの型** | `setlist_shape` | 曲数・区切り・1 曲目/アンコール/締め・ソロ枠・主演の歌唱曲数と割合 |
| | `song_position_profile` | その曲が公演のどこで歌われるか (序盤/中盤/終盤・1 曲目・締め) |
| | `co_performed_songs` | 一緒に歌われやすい曲 (分母つき) |
| | `setlist_diff` | 2 公演の比較 |
| **集計** | `stats` | 披露回数/出演公演数/公演別曲数ランキング・年別公演数・CD シリーズ |
| **歌詞** | `search_lyrics` | 歌詞に語を含む曲 + 断片 (本文は返らない)。AND/OR/括弧が使える。`show_id` / `event_id` / `idol_id` で**母集団**を決められる |
| **登録 (ドラフト)** | `propose_song` / `propose_event` / `propose_setlist` / `propose_idol` / `propose_fix` / `check_proposals` | `data/` に JSON を書いて `--check` まで。反映はオーナーの操作 |

## 2. レシピ

### A. 「◯◯の主演公演が決まったらどんなセトリ?」

いちばん手数が要る問い。**予想はツールが返さない** (返すのは過去の事実) ので、材料を集めて呼び手が組む。

```
1. resolve --query 伊吹翼                     → ml_伊吹翼
2. get_idol --id ml_伊吹翼                    → 人物像。ここが公演のコンセプトになる
                                                (翼 = 「めざせモテモテハッピーライフ」/ angel / 趣味は遊びの計画)
3. list_shows --idol_id ml_伊吹翼 --cast_role lead
                                              → 0 件。no_hits.relax_one が
                                                「主演公演は 8 本 / 翼は 96 公演」と教える
4. setlist_shape --cast_role lead             → 型 (下表)
5. idol_songs --idol_id ml_伊吹翼 --role solo  → ソロ枠に置ける持ち駒
6. songs_for_cast --idol_ids <出演候補>        → 枠を実名で埋める
7. search_lyrics --query "空 翼" --brand ml    → 名前・情景から曲を拾う
8. get_show --id <近い型の公演>                → 1 本精読して並びを掴む
```

4 で出る主演公演の型 (標本 8 公演):

| | min | median | max |
|---|---|---|---|
| 曲数 | 23 | 23 | 39 |
| ソロ枠 (`solo_slots`) | 1 | 2 | 7 |
| うち主演のソロ (`lead_solo_slots`) | 1 | 2 | 7 |
| 主演 1 人の歌唱曲数 | 10 | 17 | 22 |
| 同 割合 (`lead_share_percent`) | 43 % | 51 % | 74 % |
| 他の出演者 1 人 | 6 | 8 | 10 |
| 同 割合 | 17 % | 35 % | 43 % |

**曲数と割合は対で読む。** 主演公演の規模が 23 曲と 39 曲に割れているので、曲数だけ見ると
「23 曲中 14 曲」より「39 曲中 17 曲」が大きく見える。

### B. ライブの組まれ方を読む

セトリがどう作られているかは、`get_show` を何本か精読するのが速い。主演公演で実測した骨格:

- **セトリの 50〜65 % が主演の持ち歌**。うち 3〜5 曲は**主演が歌わず他のメンバーがカバー**する
  (`ふたり繋ぐ星座` は北上麗花のソロ曲だが 12th DAY1 では静香・のり子・風花が歌う)
- 主演の**ソロ新曲は 20〜21 曲目**で固定 (23〜24 曲の公演)
- **765AS のカバーが 3.0 曲/公演**、8 公演すべてにある
- 新曲は 3.1 曲/公演
- **締めの曲は 8 公演すべて重複なし**
- 歌唱が原唱どおりなのは 2 割。**ユニット名で編成を固定してはいけない**
  (ただし `アイル (Harmonized ver.)` のように由来のある組み合わせは動かない)

### B-2. 公演のコンセプトを読む (歌詞から)

セトリのテーマは曲名だけでは見えない。**同じ語で 2 つの公演を測ると差が出る**。

```
search_lyrics --query 月 --show_id <13th DAY2>
→ scope: DAY2 (二階堂千鶴主演) … 23 曲中 8 曲
```

13thLIVE の 2 日間を同じ物差しにかけた実測 (各 23 曲中):

| 歌詞の語 | DAY1 高山紗代子 | DAY2 二階堂千鶴 |
|---|---:|---:|
| **月** | 2 | **8** |
| **夜** | 5 | **11** |
| **恋・愛** | 10 | **15** |
| **走る・駆ける** | **6** | 2 |
| 空 / 星 / 夢 | 10 / 7 / 12 | 11 / 8 / 14 |

`空` `夢` `星` はアイマスの歌詞に普遍的なので差が出ない。**差が出た語がコンセプト**。
紗代子 (princess・「全力で前へ進み続ける熱血系」) は走る、千鶴 (fairy・「気高き
ゴージャスアイドル」) は月と夜 — 主演のキャラクターが歌詞のレベルまで降りている。

同じライブの 2 日間でも `setlist_diff` で共通するのは `蝶々むすび` 1 曲だけだった。

### C. 曲を探す

| 探し方 | ツール |
|---|---|
| 名前・綴りから | `resolve` → `get_song` |
| 歌詞の語から | `search_lyrics --query "翼" --brand ml` |
| その人の持ち歌の中で歌詞から | `search_lyrics --query 翼 --idol_id ml_伊吹翼` → 持ち歌 51 曲中 6 曲 |
| まだ歌われていない曲 | `search_lyrics --query 夏 --brand ml --max_performances 0` → 2 曲 |
| 誰の持ち歌か | `idol_songs --idol_id … --role original` (`solo` でソロだけ) |
| この顔ぶれで歌えるか | `songs_for_cast --idol_ids …` |
| いつ歌われたか | `song_performances` |
| どこで歌われるか (曲順の傾向) | `song_position_profile` |
| 一緒に来やすい曲 | `co_performed_songs` |

### D. データを足す

```
propose_song / propose_setlist / propose_fix …  → data/ に JSON を書いて --check
check_proposals                                 → 溜まったドラフトを検証し直す
```

`source` (一次ソースの URL) と `source_quote` (逐語引用) が**構造上の必須**。
反映 (`--apply --push`) はオーナーの操作で、ツールからは実行しない。

## 3. 落とし穴

- **id を推測しない。** 表示名と id は別 (`ml_ロコ` は無く `ml_伴田路子`)。必ず `resolve` か
  `get_*` が返した id を使う。
- **曲名の exact 一致は記号で外れる。** `シャル・ウィー・ダンス？` (全角) `メメント？モメント`
  `俠気乱舞` (異体字) `If I…` (三点リーダ)。`search` の部分一致で確かめてから使う。
- **0 件は「無い」ではない。** 自由文なら `no_hits.terms` / `unmatched_terms`、軸で絞ったなら
  `no_hits.relax_one` (軸を 1 つ外したときの件数) を読む。
- **`setlist_items.position` は公演をまたぐ通し番号。** 曲順はツールが返す `track_number` を使う
  (生の値を出すと「12852 曲目」になる)。
- **`solo_slots` は「その日 1 人で歌った曲」。** 原唱者が 1 人でも複数人で歌えばソロ枠ではない。
- **歌詞本文は返らない。** 返るのは断片 (1 曲 2 本まで)。行番号も前後の行も付かない。
- **`search_lyrics` は母集団を指定しないと全曲から返る。** サーバ側で 200 件当たることも
  あるので、公演やアイドルと突き合わせるときは `show_id` / `event_id` / `idol_id` を付ける
  (付けると `scope.songs` が返り「23 曲中 8 曲」と読める)。
- **派生曲 (`(◯◯ Ver.)` 等) は返らない。** 親と歌詞が同じで一覧が埋まるため
  (`list_songs` と同じ扱い)。`アイル(Harmonized ver.)` も親の `アイル` で当たる。
- **バイナリを作り直しても、動いている MCP クライアントには反映されない。**
  `imas-mcp tools` に出るのにクライアントから見えないならこれ。クライアント側で再接続する。
